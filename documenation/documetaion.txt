## 1. Overall Goal

The goal is to build a **CNN accelerator on an FPGA in SystemVerilog**, starting from fundamental hardware blocks and gradually progressing toward a small but complete convolution engine.

The approach is intentionally incremental:

> **BRAM → MAC → 3×3 convolution → parallel MACs → adder tree → pipeline → sliding window → line buffers → multiple filters → CNN layer**

The purpose is not just to make a CNN accelerator work, but to understand **why each architecture works and what trade-offs it has**.

# 3. DSP / MAC Block

You then built the DSP block.

The basic operation is:

[
ACC \leftarrow ACC+(A\times B)
]

where:

```text
A = read_data_port1
B = read_data_port2
```

Conceptually:

```text
       read_data_port1
              │
              ├──────┐
              │      │
              ▼      ▼
             ┌────────┐
             │MULTIPLY│
             └────┬───┘
                  │
                  ▼
             ┌─────────┐
             │   ADD   │◄──── previous accumulator
             └────┬────┘
                  │
                  ▼
             ACCUMULATOR
```

Your accumulator is 27 bits:

```text
accum_length = 27
```

which gives enough room for the accumulation we are currently testing.

---

# 4. Why You Used the Negative Clock Edge

You deliberately chose:

```text
posedge clock
```

for the BRAM read and:

```text
negedge clock
```

for the MAC.

The idea is:

```text
Positive edge
     ↓
BRAM reads memory
     ↓
read_data_port1/2 update
     ↓
Negative edge
     ↓
DSP multiplies the two values
     ↓
Accumulator updates
```

So you're effectively using the two edges of the clock to separate the BRAM read and MAC operation.

This was an important architectural decision.

---

# 5. Connecting the Accumulator to `out`

We discussed that the accumulator itself needs to retain its value because it is state.

Therefore the architecture is:

```text
                accumulator
                    │
                    ▼
                   out
```

The accumulator is the register.

`out` is simply exposing that register's current value.

You **don't need another register for `out`** unless you specifically want another pipeline stage.

# 8. Why `$display` Printed 20 While the Waveform Showed 40

This was also resolved.

Your accumulator uses a nonblocking assignment:

```text
accumulator <= accumulator + product;
```

At the clock edge, the old accumulator value is temporarily visible during the current simulation scheduling region.

So `$display` could see:

```text
20
```

while the waveform, after the nonblocking update completed, showed:

```text
40
```

This is a **SystemVerilog simulation scheduling issue**, not an error in your MAC.

Using a small delay or `$strobe` when printing the final result allows you to see the updated value.

# 10. Why This Matters for CNNs

A CNN convolution is fundamentally a dot product.

For a 3×3 kernel:

[
Y=
X_0W_0+
X_1W_1+
X_2W_2+
X_3W_3+
X_4W_4+
X_5W_5+
X_6W_6+
X_7W_7+
X_8W_8
]

That is simply:

[
\boxed{Y=\sum_{i=0}^{8}X_iW_i}
]

Your current MAC already performs:

[
ACC\leftarrow ACC+X_iW_i
]

Therefore, the MAC you've built is the **fundamental computational unit of the CNN accelerator**.

# Stage 6 — Adder Tree

Once we have nine products:

[
P_0,P_1,\ldots,P_8
]

we need:

[
P_0+P_1+\cdots+P_8
]

We'll implement a proper **reduction/adder tree**.

Conceptually:

```text
P0 ─┐
    ├─ADD──┐
P1 ─┘      │
           ├─ADD──┐
P2 ─┐      │      │
    ├─ADD──┘      │
P3 ─┘             ├── ...
                  │
P4 ─┐             │
    ├─ADD──┐      │
P5 ─┘      │      │
           ├─ADD──┘
P6 ─┐      │
    ├─ADD──┘
P7 ─┘
```

This introduces **combinational depth and timing**.
